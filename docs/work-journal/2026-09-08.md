# 2026-09-08

A records day, with no code changed. The tree had been idle since the debugger
view landed on 2026-08-18, and the previous way in, `handoff.md` at the root,
had last been written on 2026-08-08, before the three commits it would have
needed to describe. So the day started by asking what the tree knew that
nothing durable had written down, and ended by giving the repository the
records the other projects in this workspace already keep. Everything below
sits on a branch, `records-and-audit-findings`, cut from `main` at the
debugger commit and not yet on the remote.

## The audit, and where its findings went

The sweep covered the span from the last handoff to the debugger view. Its two
findings were both about the toolkit rather than any one subproject, which is
why they went on the root roadmap under a new "Open" section and not split
three ways. Split, the shared cause would have been invisible.

The first is that the records still describe a two-project repository. `emu/`
has been the most active subproject since August, and root `README.md` has
never mentioned it. The root roadmap's own opening note has the same gap, and
`emu/ROADMAP.md` opens with "Nothing here is implemented yet" above a build
order that is nearly all struck through.

The second is that none of the four documented ways to run this toolkit's
tests actually run them. The shape is the same each time: a runner that
reports success without having checked anything. `asm/`'s `make test` pipes
every demo into a script with no command-line entry point. The per-demo
`test_*.py` scripts look for the assembler where a sandbox once kept it and
not where this tree does. `C/`'s test loop exits zero on a `BRK` halt and
compares nothing. `C/build.sh` looks for `c64asm` in a directory where it has
never been built. The first of these is worth dwelling on. The identical trap
had already been found and fixed once, in `CLAUDE.md`'s documented `C/` test
command, and the fix is recorded in the root roadmap's "Recently done". The
copy in `asm/Makefile` was never looked for. That is scored in the postmortem.

What the audit verified and found sound is worth stating too, since the
findings above could read as if nothing works: all nine `emu/` gates pass with
the boot gate at its recorded 180030 cycles, the Python and C assemblers agree
byte for byte on every example, and the emulator's disassembler table matches
the assembler's at 56 mnemonics and 151 opcode bytes.

## The setup, and what it left alone

`/project-setup` ran in its ensure mode, adding only what was absent. Two of
the five record roles were: a postmortem and a journal. Both were created
empty of entries, with an opening note each stating its job, since setup day
is not a day either had anything to say about. The postmortem is scoped to the
whole toolkit rather than per subproject, because the mistakes worth keeping
here have crossed the boundary before: a `cc64` program was what first
exercised `c64emu`'s program-injection path, and a real C64 was what caught a
zero-page assumption `mini6502.py` had been happy with.

The other three roles were already filled, in shapes of their own, and were
left as they are: roadmaps as a set of four, one per component and one at the
root; "what was built" as struck-through entries and a "Recently done" section
inside those roadmaps rather than a separate ledger; and a changelog for the
assembler only. `CLAUDE.md` gained a section naming that set and saying that
each record's own opening note is its specification. The "Start here"
paragraph pointing at a daily standup, and the `.gitignore` rule for
`scratch/`, had been sitting uncommitted in the working tree since 2026-09-04.
They went in today alongside the directory they describe, which makes the
pointer true for the first time. An MIT license went in as well, and made one
sentence in `emu/tests/cpu/README.md` false, so that sentence was reworded in
the same commit.

`handoff.md` was left where it is. It is the older convention this journal and
the standup replace, and retiring it is its owner's call.

## The second sweep

A second pass re-ran every number the first one had committed. Five of six
held exactly. The sixth was the claim that all seven of `emu/`'s build-order
steps were done. Six are; the seventh, SID, is everything but the analog
filter and says "in progress". The finding's point survived, since the
roadmap's opening sentence is wrong either way, but the count had been written
about seven things without checking each of the seven. It is corrected, and
the postmortem has it.

## Four defects, and why they are not in the postmortem

The audit had also read the diff of the span, and found four defects in the
code that had been reported in conversation and written nowhere: two in
`C/bin/lib/sound.h`, where volume writes clobber the filter nibble and
silencing kills a note's release tail, and two in the emulator, where the
debugger's memory pane reads I/O registers that change state when read, and
reset only resets the CPU. Each was confirmed against the source before being
recorded. They went on the roadmap of the subproject each belongs to, beside
their siblings, rather than on the root roadmap, because each is scoped to one
subproject. They did not go in the postmortem, whose opening note says it is
not a bug log: these are unfixed defects, not scored learnings. The one thing
they share, that the tests which should have caught them only read back what
they wrote, is the same shape as the audit's second finding.

## Where the day ends

The closeout ran the nine gates again in place and they pass. It found two
untracked files the day had not mentioned: `handoff.md`, as above, and a
Finder bookmark to the open-roms project under `emu/resources/`, which does
not belong in the tree. The branch has no upstream, so nothing from today has
left this machine.
